# 7. 파일 안내와 재현

> [← 이전](06_검증과_결과_해석.md) · [index](index.md) · [다음 →](08_용어와_자주_묻는_질문.md)

---

먼저 기존 결과를 열어 보고, 직접 확인할 필요가 있을 때 같은 입력으로 다시 실행하면 된다.
**재현**은 같은 원본 · 설정 · 도구 조건으로 결과를 다시 얻는 일이다. 현재 측정 원자료를 덮어쓰지 않도록
새 출력은 저장소 밖 작업 폴더에 만드는 예제를 쓴다. 아래 로컬 명령은 저장소 최상위 폴더에서 실행한다.

## 7.1 무엇을 보려면 어떤 파일을 여나

| 알고 싶은 것 | 열 파일 · 위치 | 읽는 방법 |
|---|---|---|
| 입력 카메라가 보낸 원본 | `software/datasets/*.dvs` | 바이너리이므로 파서로 읽는다. 원본은 수정하지 않는다 |
| 입력의 이벤트 수 · 시각 · SDK 일치 | [입력 해석 묶음](../../software/dvs_data/2026-10-28_dvs_read/2026-10-28_dvs_read.md) | `summary.txt`, `sdk_check.txt`, 시점별 그림 |
| 최종 장면 1 설정과 전체 결과 | [막대 중심 골든 묶음](../../software/golden_data/2026-10-28_golden_bar_center/2026-10-28_golden_bar_center.md) | `center.txt` → `rotation.csv` → `world.png` · `verify.txt` |
| RTL 입력과 기댓값 | 위 묶음의 `vectors/` | 파일 역할은 [3장 3.6절](03_좌표_변환과_월드_메모리.md#36-rtl-테스트벤치-벡터) |
| 최종 회로 코드 | [wl_top.v](../../hardware/src/wl_top.v) | 연결을 먼저 보고 `wl_decode` → `wl_xform` → `wl_accum` 순서로 읽는다 |
| 회로에 입력을 넣고 비교하는 코드 | [tb_worldlock.v](../../hardware/testbench/tb_worldlock.v) | 입력 공급, 처리 완료 대기, 메모리 칸 비교 |
| 장면 1 RTL 전체 검증 로그 | [RTL 검증 묶음](../../hardware/sim/results/2026-10-28_bar_center/evidence.md) | `result.txt`, `empty_frames.txt`의 각 시험 판정 |
| 장면 2 설정과 검증 | [골든 묶음](../../software/golden_data/2026-10-29_scene2_golden/2026-10-29_scene2_golden.md), [RTL 묶음](../../hardware/sim/results/2026-10-29_scene2/evidence.md) | 고정 중심과 전체 입력 시험 결과 |
| 최종 타이밍 · 면적 · 전력 | [최종 합성 · 배치 근거](../../hardware/syn/results/2026-10-29_pnr/evidence.md) | 측정 조건과 해당 `.rpt`를 함께 본다 |
| 왜 다른 방법을 버렸나 | [설계 근거](../reports/01_설계_근거.md) | 선택별 처음 방법 · 지금 방법 · 비교 결과 |

폴더 이름의 날짜는 결과를 만든 날짜다. 원본 `.dvs` 이름의 날짜는 제공된 녹화 파일의 이름이다.
예를 들어 9월 원본을 10월에 분석해 10월 결과 폴더를 만들었으므로 날짜가 달라도 같은 입력일 수 있다.
`evidence.md`는 그 폴더의 도구 · 실행 조건 · 로그 위치를 알려 주는 근거 안내문이다.

`.csv`는 행과 열을 쉼표로 나눈 표, `.npy`는 NumPy가 읽는 숫자 배열, `.hex`는 16진수 텍스트다.
`.txt`와 `.rpt`는 사람이 읽을 수 있는 설정 · 결과 · 도구 보고서이고, 그림 파일은 숫자를 보기 좋게 표시한 자료다.
같은 묶음 안에도 전체 녹화 결과와 잘라 낸 시험 구간 결과가 함께 있으므로 구간을 확인한다.

## 7.2 가장 짧게 확인하기

Python의 입력 읽기는 NumPy를 쓴다. 골든 모델의 그림 · 막대 검증에는 SciPy와 Matplotlib도 쓴다.
RTL 실행에는 Verilator 또는 Vivado의 xsim이 필요하고, 합성 · 배치는 대회 서버의 도구와 라이브러리가 필요하다.
도구 버전은 [5장](05_SRAM과_합성_결과.md)과 각 근거 묶음의 `evidence.md`에 있다. 원본 녹화(`.dvs`, 각 약 100 MB)는 주최 측 데이터라 저장소에 넣지 않았다.

원본 녹화의 입력량을 읽어 보려면 다음 명령을 실행한다. 파일 내용은 바꾸지 않는다.

```bash
python3 software/dvs_develop/dvs_read.py software/datasets/2026-09-22-16-42-44-DELTA.dvs
```

저장돼 있는 기본 시험 벡터로 RTL을 확인하려면 다음 중 설치된 시뮬레이터의 명령을 실행한다.

```bash
hardware/sim/run_sim.sh verilator tb_worldlock
```

```bash
hardware/sim/run_sim.sh xsim tb_worldlock
```

벡터 경로를 생략하면 최종 장면 1 묶음의 기본 구간을 쓴다. 성공하면 마지막에 `RESULT PASS`가 나온다.
이 명령 한 번은 기본 구간 시험이며, 전체 녹화를 검증한 것과는 범위가 다르다.

실행 스크립트는 경로 공백으로 인한 도구 문제를 피하려고 소스를 `~/wl_build/` 아래에 복사해 빌드한다.
동일한 시뮬레이터 · 테스트벤치의 작업 폴더를 공유하므로 이 러너를 동시에 여러 개 실행하지 않는다.

## 7.3 골든 결과를 별도 폴더에서 다시 만들기

아래 예제는 **이미 구한 최종 회전각과 중심을 그대로 사용**해 정수 모델과 기본 시험 벡터를 다시 만든다.
회전각 추적 알고리즘부터 새로 맞추는 절차는 아니다. 단계별로 실행하면 어느 부분에서 결과가 달라졌는지 찾기 쉽다.

```bash
task_output="$HOME/wl_build/worldlock_reproduce"
task_seed="software/golden_data/2026-10-28_golden_bar_center"
task_dvs="software/datasets/2026-09-22-16-42-44-DELTA.dvs"
mkdir -p "$task_output/golden"
cp "$task_seed/rotation.csv" "$task_seed/center.txt" "$task_output/golden/"
python3 software/golden_develop/golden.py "$task_dvs" "$task_output/golden" 500 540
python3 software/golden_develop/verify_world.py "$task_dvs" "$task_output/golden"
```

`500 540`은 프레임 500부터 539까지를 **RTL 시험 벡터로 자르는 범위**다. 이 호출에서 `world.npy`는 여전히
녹화 전체 결과로 만들어진다. 마지막 `verify_world.py`는 막대 측정과 결과 그림을 같은 새 폴더에 쓴다.
기존 근거 묶음은 읽기만 하고, 재실행 결과는 `worldlock_reproduce` 폴더에서 갱신된다.

이어서 새로 만든 벡터를 RTL에 넣는다. 위 변수를 설정한 같은 셸에서 실행한다.

```bash
hardware/sim/run_sim.sh verilator tb_worldlock "$task_output/golden/vectors"
```

회전각 추적부터 다시 할 때는 [최종 골든 묶음의 생성 순서](../../software/golden_data/2026-10-28_golden_bar_center/2026-10-28_golden_bar_center.md)를 본다.
그 절차는 앞 단계 분석 묶음을 입력으로 받는다. `golden.py`만 실행한다고 원본에서 회전각까지 새로 찾아 주지는 않는다.

## 7.4 전체 녹화와 경계 시험

현재 준비된 경계 시험과 두 시뮬레이터의 전체 시험을 모두 실행하는 명령은 다음과 같다.

```bash
hardware/sim/regress.sh
```

기본 벡터 외에 전체 녹화 · 중심 변경 · 빈 프레임 · 기준 설계용 입력이 없으면 스크립트가
`~/wl_build/` 아래에 만든다. 두 시뮬레이터가 모두 설치돼 있어야 전체 절차를 실행할 수 있다.
전체 입력은 파일과 메모리 사용량이 기본 구간보다 크므로, 빠른 확인이 목적이면 7.2절부터 실행한다.

직접 전체 장면 1 벡터만 만들어 Verilator로 실행할 수도 있다.

```bash
task_full="$HOME/wl_build/worldlock_reproduce/full"
python3 software/golden_develop/golden.py vectors \
  software/datasets/2026-09-22-16-42-44-DELTA.dvs \
  software/golden_data/2026-10-28_golden_bar_center 0 all "$task_full"
VFLAGS=-GMAXW=33554432 hardware/sim/run_sim.sh verilator tb_worldlock "$task_full"
```

`vectors` 모드는 입력과 기댓값만 새로 만든다. `0 all`은 파일 시작부터 모든 프레임이고,
`MAXW`는 테스트벤치가 보관할 최대 입력 워드 수다. 회로의 해상도나 실제 SRAM 용량을 바꾸는 값이 아니다.

장면 2 전체를 재현할 때는 [장면 2 RTL 근거의 명령](../../hardware/sim/results/2026-10-29_scene2/evidence.md)을 쓴다.
원본과 골든 묶음을 장면 2로 바꾸고 `+cx`, `+cy`도 그 장면에 맞춰야 한다. 기본 회귀 시험에 있는
장면 2 시작 구간의 위상 0 시험은 **입력 디코더의 시작 조건 시험**이므로, 장면 2 전체 정렬 검증과 구분한다.

## 7.5 로그에서 무엇을 확인하나

| 출력 | 뜻 | 볼 부분 |
|---|---|---|
| `loaded … words, … phases` | 읽어 들인 워드 수와 위상 수 | 선택한 프레임 구간과 맞는가 |
| `frames … (phases …)` | 끝난 프레임과 실제로 쓴 위상 | 빈 프레임이나 카운터 뜀에서도 순서가 맞는가 |
| `cycles` | 입력 처리에 사용한 클럭 수 | 입력에 빈 클럭을 넣었는지, 같은 조건인지 |
| `updates` | SRAM 값을 고친 횟수 | 합치면 이벤트 수보다 작을 수 있다 |
| `accesses` | 읽기 · 쓰기 접근 횟수의 합 | 이벤트 수나 갱신 수와 같은 단위가 아니다 |
| `stall cycles` | SRAM 뱅크 충돌로 기다린 클럭 | 포트 제약에 따른 처리 비용 |
| `dropped` | 좌표가 저장 범위 밖이라 버린 이벤트 수 | 카운터 포화로 더하지 못한 수와 다르다 |
| `memory sum`, `max` | 최종 칸 값의 합과 최댓값 | 구간 · 포화 비트 수에 따라 달라진다 |
| `mismatches` | 골든과 값이 다른 칸 수 | 0이어야 한다 |
| `RESULT PASS` | 해당 시험의 최종 판정 | 각 시험에 모두 있는지 본다 |

합계가 맞아도 칸별 `mismatches`가 있으면 통과한 것이 아니다. 두 시뮬레이터 사이에는 시험 시작 · 끝을 세는
시점 때문에 전체 클럭 수가 한 클럭 다른 보관 결과가 있다. 메모리 값과 조건을 함께 비교한다.
PC에서 시뮬레이션이 돌아간 실제 경과 시간은 회로의 클럭 수나 목표 주파수와 다른 값이다.

## 7.6 합성 · 배치 결과 재현과 문서 검사

대회 서버 작업 폴더에서 합성과 배치를 실행하는 기본 명령은 다음과 같다. GPDK045 라이브러리와 Cadence 도구는
대회 서버(주최 측 제공)에 있다.

```bash
hardware/syn/run_genus.sh wl_top
hardware/syn/run_lec.sh wl_top
hardware/syn/run_innovus.sh wl_top
```

이 기본 명령만으로 [5장](05_SRAM과_합성_결과.md)의 활동 중 전력과 같은 값을 재현했다고 보지는 않는다.
활동 기반 전력에는 **동일 구간의 VCD 파형과 맞는 신호 경로**가 필요하다. VCD는 시뮬레이션 중 신호가
언제 0 · 1로 바뀌었는지 적은 파일이다. 최종 실행 때 쓴 `VCD`, `VCD_SCOPE`, 배치 뒤 넷리스트 GLS 명령은
[최종 합성 · 배치 근거](../../hardware/syn/results/2026-10-29_pnr/evidence.md)에 있다.
그 문서의 코너 · 툴 버전 · SRAM 모델까지 맞춰 비교한다.

설계 문서를 고쳤을 때는 다음 검사를 실행한다.

```bash
python3 docs/check_docs.py
```

파일 · 절 링크와 그림 참조 등을 검사한다. 문장의 기술적 주장을 자동으로 검증하는 도구는 아니므로,
인용한 절이 실제로 그 주장을 뒷받침하는지는 별도로 읽고 확인한다.
