# Bio-mimic Neuron을 위한 AER 통신 방식 설계

**2026 전국 대학생 AI 반도체 회로 설계 경진대회 · 디지털 트랙 · 1차 제출**

---

## 1. 개요

### 1.1 과제

> 전통적인 AER 방식을 **분석**하고 → **문제점 도출** → **개선방법** → **개선된 AER 설계 방향 제시**

### 1.2 먼저 정의해야 할 것 — "AER 통신 방식"의 층위

AER(Address Event Representation)이라는 말은 두 개의 서로 다른 층위를 가리키는 데 혼용된다. 설계 대상을 정하려면 먼저 구분해야 한다.

| 층위 | 내용 |
|---|---|
| **데이터 표현 포맷** | 이벤트 튜플 `{x, y, polarity, t}` |
| **readout 메커니즘** | 그 포맷을 만들어내는 회로 — 비동기 arbiter / 동기 scan |

iniVation 백서는 이 점을 명시한다: *"비동기든 동기든, 이벤트 출력 데이터는 동일한 address event representation (AER) 포맷이다."*

**즉 "AER 통신 방식 설계" = readout 메커니즘 설계**이며, 본 보고서의 대상이다.

### 1.3 설계 목표의 재정의

통상 AER 개선은 "타임스탬프 분해능을 높이자"로 접근하지만, 물리적으로 그 방향은 이득이 없다.

> 픽셀 front-end 잡음(photon shot noise, circuit thermal noise, temporal contrast threshold mismatch)은 **근본 물리에 의해 정의되며 회피 불가능**하고, 통상 조명에서 그 크기는 **수백 µs** 수준이다. 따라서 **1 µs나 1 ns 같은 작은 타임스탬프 단위는 100 µs 수준의 거친 단위보다 ground truth에 대해 추가 정보를 거의 주지 못한다.**
> — iniVation White Paper, May 2020

**→ 줄여야 할 것은 타임스탬프 단위가 아니라 readout latency, 특히 worst-case다.** 본 설계의 목표를 여기에 둔다.

### 1.4 왜 Bio-mimic Neuron에 AER이 필요한가

- 뉴런 발화율은 ~kHz, 디지털 버스는 ~MHz–GHz. **다섯 자릿수 격차**가 시분할 다중화를 필연으로 만든다.
- CMOS 인공 감각 수용체의 최대 스파이크율은 약 1 kHz이며, 밀집 DVS 버스트도 마이크로초 스케일에서 동작한다.
- 즉 AER의 설계 여유는 크지만, **동시 발화(버스트) 시의 worst-case**가 실제 병목이다.

## 2. 전통 AER 분석

### 2.1 성능 프레임 (Boahen 2000)

통신 채널의 4대 지표:

| 지표 | 정의 |
|---|---|
| **Capacity** | 최대 spike 전송률 = 최소 communication-cycle time의 역수 |
| **Latency** | 발생 → 도달 시간 분포의 **중앙값** |
| **Temporal Dispersion** | 그 분포의 **표준편차** |
| **Integrity** | 올바른 목적지로 전달된 비율 |

이 넷을 합쳐 **Throughput = 사용 가능한 채널 capacity의 비율**로 정의한다.

**정량 결과 (문제점 도출의 근거)**
- 비중재(ALOHA형) 채널 최대 throughput = 채널 capacity의 **18%**
- 중재 채널은 **95% 부하**에서도 동작하나, 그 지점에서 latency 10.5 cycle, **σ = 9.8 cycle**
- 즉 **latency ≈ temporal dispersion** — 타이밍 정밀도 손실이 전통 AER의 본질적 대가

### 2.2 구조 계보

| 세대 | 방식 | 동작 | 한계 |
|---|---|---|---|
| 1 | Word-parallel AER | row 중재 → column 중재 → X,Y 주소 동시 전송 | 핀 수 많음, 이벤트마다 중재 2회 |
| 2 | Word-serial burst-mode | 공통 주소 1회 전송 후 나머지 연속 전송 | 핀 절반, 대역폭↑ |
| 3 | Group-AER | 픽셀을 그룹으로 묶어 전송, 주소 비트 감소 | 32 → 12 → 8 bit/event |
| 4 | Token ring | mutex ring을 token이 순회, 공유 counter가 주소 생성 | sparse에서 token 이동거리 = 지연 |
| 5 | Hierarchical Token Ring | leaf ring + 상위 ring 계층화 | sparse·burst 동시 대응 |
| 6 | FP-AER | configuration bit로 event/frame/hybrid 재구성 | custom EDA 의존 |
| 7 | Scan readout | arbiter 폐기, 순차 column scan | 저활동 응답성 손실, 상시 static power |

### 2.3 산업계의 궤적 — 문제와 해법이 이미 공개되어 있다

삼성 DVS 세대별 변화가 "전통 AER의 문제 → 개선"을 그대로 보여준다.

| | Gen1 (2014) | Gen2 (2016) | Gen3 (2018) |
|---|---|---|---|
| Readout | Row/Column **Arbiter** | 디지털 합성 **G-AER** | **Digital Scan Logic** |
| 성능 | Max 6.5 Meps | Max **300 Meps** | Effective > 2,000 fps |
| 픽셀 메모리 | 없음 | 없음 | **Global hold + Global reset** |
| 전력 | 15 mW | 80 mW | 65 mW |

Gen1 → Gen2에서 **46배**, Gen2 → Gen3에서 **arbiter 자체를 폐기**했다.

## 3. 문제점 도출

각 항목을 **① 산업계 문제 정의 ② 학술적 근거 ③ 본 설계에서의 실측** 세 축으로 뒷받침한다.

### P1. Unfair arbitration → artifact & delay

중재 순서가 고정되면 특정 픽셀이 항상 늦게 서비스되어 **공간적으로 구조화된 아티팩트**가 된다.

**실측**: 8×8 배열에 64개 이벤트를 동시 발화시키고 200회 반복한 결과, 각 픽셀의 서비스 순위가 **분산 0으로 완전히 고정**되었다. 순서는 주소의 **비트 역순(bit-reversal) 순열**이며, 버스트 지연이 닫힌 형태로 표현된다:

```
L(ch) = τ₀ + bitrev(ch) × Δ
```

DEPTH=6(64채널)에서 ch0은 항상 **3.1 ns**, ch63은 항상 **120.3 ns** — **39배 차이가 채널 인덱스만으로 결정**된다.

> **직렬화 지연 자체는 불가피하다.** 총 배출 시간은 N·Δ이고 누군가는 마지막이다. **문제는 그 배정이 고정이라는 것**이다.

### P2. AER induced latency — 이벤트당 다중 핸드셰이크

개별 픽셀마다 row·column 핸드셰이크를 반복하고, 인터페이스 대역폭이 이를 다시 제한한다.

### P3. Motion artifact — 이벤트 생성시각 ≠ readout 시각

고이벤트율에서 두 시각의 불일치가 이미지 아티팩트로 나타난다.

### P4. Timestamp error

타임스탬프는 readout 시점에 찍히므로 **오차 = readout latency**다. 그런데 **일정한 지연은 오차가 아니다**(보정 가능). 남는 것은 **산포**다.

**실측 — 산포는 두 성분으로 분해된다:**

```
σ²_total = σ²_between + σ²_within
  between : 채널별 평균의 분산 = 고정 공간 패턴, 공정한 중재로 제거 가능
  within  : 채널 내부 분산     = 큐잉 잡음, 주어진 Δ에서 불가피
```

| 자극 | 아티팩트 성격 | 중재 정책으로 제거 가능? |
|---|---|---|
| **Poisson** (배경 잡음 이벤트) | 잡음, 공간적으로 균일 (σ_between이 σ_total의 4~14%) | ❌ Δ가 정하는 물리적 하한 |
| **동기 버스트** (전역 조도 변화) | 고정 공간 패턴 (비트역순) | ✅ 회전 우선순위로 제거 |

**실제 DVS는 둘 다 겪는다.** 기존 자료가 곡선 하나로 보여주는 timestamp error는 이렇게 **"고칠 수 있는 것"과 "물리적 하한"으로 쪼개진다.**

### P5. Overflow / event loss

이벤트율이 회로 최대 throughput을 초과하면 손실이 발생한다. 본 설계 실측에서 포화 시 손실률은 offered rate 대비 `1 − 용량/offered` 를 0.7%p 이내로 따라간다.

### P6. log₂(N) 중재 지연 → 확장성

**실측**: 무부하 경로지연 τ₀는 depth에 정확히 선형이다.

```
τ₀ = 0.520 ns × depth      (depth 3~7, 차분 5구간 전부 동일, 절편 0)
```

### P7. Redundant events

노이즈·bad pixel·flicker·다중 검출이 의미 없는 이벤트를 만든다.

### P8. Encoder 부하 / 핀 수 / 전력

플랫 트리는 N−1개의 arbiter 셀을 요구한다. 64×64 배열이면 **4,095개**다.

### P9. Metastability — 강건설계 축

**실측**: structural cross-coupled NAND에 두 요청이 같은 시각에 도착하면, 두 NAND 지연이 동일해 `n1`·`n2`가 함께 0 → 함께 1로 진동하며 래치되지 않는다. `n1 == n2`인 동안 **두 grant가 모두 0**이 되어 모든 노드가 `sel = 0`을 내보내고 **주소가 all-zeros로 축퇴**된다.

관측이 정확히 일치했다 — 요청이 없거나 한 번에 하나씩 넣는 시험은 통과하고(tie가 발생하지 않으므로), 8개 동시 발화 시험만 실패하며 모든 오류가 채널 0을 가리켰다.

> **이것이 "표준셀 합성으로는 arbiter를 보장할 수 없다"의 직접 증거다.** 준안정성은 모델링 불편이 아니라 회로의 물리적 성질이고, 시뮬레이터에 그것이 없다는 사실이 곧 **실제 셀에 아날로그 준안정 필터가 필요한 이유**다.

### P10. 물리적 상한 — §1.3에서 정의한 설계 목표의 근거

픽셀 front-end 잡음이 수백 µs의 검출시각 불확실성을 만들므로 타임스탬프 단위를 줄이는 것은 무의미하다. **줄여야 할 것은 readout latency다.**

## 4. 개선방법 — 세 개의 직교하는 레버

본 설계의 실측 결과, 아티팩트 저감에는 서로 **독립적인 세 가지 수단**이 존재한다.

| 레버 | 방식 | 효과 (실측) | 대가 |
|---|---|---|---|
| **① tile 분할** | 배열을 M개 독립 tile로 나눠 병렬 readout | worst-case ∝ 1/M, throughput ×M | 출력 채널 M개 (핀·serializer·면적) |
| **② 중재 공정화** | 회전/무작위 우선순위 | 버스트 편향 63.00 → 3.24 (**19.4배**) | 우선순위 상태 추적 로직 |
| **③ 타임스탬프 분리** | global hold 기반 타임스탬핑 | 버스트 편향 63.00 → **0.0000** | 저활동에서 T_frame/2 손해 |

### 4.1 레버 ②의 실측 — tie-break 정책이 편향을 잡음으로 바꾼다

동일 조건(64채널 동기 버스트 200회)에서 tie-break 정책만 바꾼 결과:

| | 고정 mismatch | LFSR (무작위) |
|---|---|---|
| 평균 rank 산포 | **63.00** (NCH−1, 최대) | **3.24** |
| 평균 버스트 latency 범위 | 3.1 ~ 120.3 ns (39배) | 58.7 ~ 64.4 ns (1.1배) |
| 버스트 간 분산 | **0** (완전 결정론적) | 통계적 잡음 수준 |

잔여 3.24는 순수 통계다 — rank 표준오차 `18.47/√200 = 1.31`, 64표본 기대 range ≈ 4.7이므로 **진짜 편향 0과 일치**한다.

**per-burst 산포는 두 경우가 동일**(63 rank)하다. 바뀐 것은 **"누가"** 이고, 그것이 설계 선택이다.

> ⚠️ **두 모델 다 실리콘이 아니다.** 실제 tie는 고정 mismatch와 열잡음이 함께 깨며 어느 쪽이 지배하는지는 RTL이 답할 수 없다. 본 측정은 **양 극단을 정량적으로 괄호친 것**이고 실제 칩은 그 사이에 있다.
> **→ 설계 결정: 공정성을 아날로그 물성에 의존시키지 않는다.** 명시적 회전 우선순위를 채택하면 mismatch·잡음 어느 쪽이 지배하든 공정성이 보장된다.

### 4.2 레버 ③의 실측 — 아티팩트는 readout을 고쳐서가 아니라 분리해서 사라진다

scan readout(global hold)에서:

```
readout RANK   min/max 0.00 / 63.00  → 산포 63.00 (가능한 최대, 완전 고정 순서)
TIMESTAMP err  min/max 1.9622 / 1.9622 ns → 산포 0.0000 ns
```

**readout 순서가 가장 경직된 상태인데도 타임스탬프 산포는 정확히 0**이다. 64 픽셀 전부 동일하다.

> **아티팩트는 readout을 공정하게 만들어서가 아니라 타임스탬프를 readout에서 분리해서 사라진다.** 회전 우선순위와는 **다르고 더 싼** 해법이며, 이것이 산업계가 Gen3에서 택한 길이다.

**Gen3의 대가도 정량화했다**: 배열이 거의 비어 있어도 σ_ts = **34.6 ns**(= T_frame/√12), worst = **236 ns**(= 2·T_frame). arbiter는 같은 조건에서 각각 0.007 ns / 3.4 ns — **5000배 / 100배** 차이다.

### 4.3 포맷 레벨 — word-serial 압축의 실제 조건

`k`(행 grant당 이벤트 수)를 측정해 두 포맷을 동시에 평가했다.

| 자극 (4픽셀 클러스터) | k | bit/event | 압축비 |
|---|---|---|---|
| 세로 엣지 | 1.04 | 5.90 | 1.02× |
| iid Poisson | 1.14 | 5.64 | 1.06× |
| 블록 | 2.14 | 4.40 | 1.36× |
| **가로 엣지** | **4.63** | **3.65** | **1.64×** |

**같은 4픽셀 엣지를 90° 돌린 것만으로 압축비가 1.02× ↔ 1.64×로 갈린다.**

- **iid Poisson의 1.14는 진짜 버스트가 아니다.** 연속 두 이벤트가 우연히 같은 행일 확률이 `1/(1−1/8) = 1.143`이며 관측값과 정확히 일치한다. 즉 공간 상관이 없으면 **버스트 형성 기여는 0**이다.
- **→ word-serial / G-AER 압축은 row 축에 정렬된 엣지에만 듣는다.** 산업계가 보고하는 평균 압축률은 장면 방향의 평균이며, 세로 엣지가 지배하는 장면에서는 이득이 거의 없다.
- **→ 신규 설계 레버**: readout 축을 row-major / column-major로 전환하면 버스트가 긴 쪽을 고를 수 있다.

**방법론적 함의**: 자극 모델이 압축 평가를 좌우한다. iid Poisson만으로 G-AER을 평가하면 **과소평가**한다.

## 5. 개선된 AER 설계 방향

### 5.1 핵심 논지 — 우열이 아니라 교차다

비동기 arbiter와 동기 scan은 어느 한쪽이 우월한 것이 아니라 **이벤트율에 따라 교차**한다. 본 설계는 이를 **자체 회로에서 실측**했다.

**timestamp error STD [ns] vs 이벤트율** (64소스, 6-bit 주소, 동일 출력단)

| offered [Meps] | flat tree | row/column | **scan** |
|---|---|---|---|
| 1 | **0.007** | 0.033 | 34.6 |
| 100 | **0.548** | 0.526 | 34.5 |
| 300 | 1.729 | **1.713** | 34.1 |
| 500 | 15.01 | **6.66** | 33.6 |
| 700 | 46.99 | 25.95 | **33.0** |
| 1000 | 40.09 | 61.70 | **31.7** |

**arbiter 곡선은 3~4자릿수 상승, scan 곡선은 평평하다.** 교차점은 flat tree ≈ **550 Meps**, row/column ≈ **780 Meps**로, 둘 다 용량 knee(400~500 Meps) 위쪽이다.

**→ 따라서 개선 방향은 "둘 중 택일"이 아니라 "교차점을 넘나드는 구조"다.**

### 5.2 제안 구조 — 부하 연동 스냅샷 타임스탬핑

> **row/column 버스트 arbiter readout + 부하 연동 경계 스냅샷 타임스탬핑. 100% 디지털.**

**동작**

| 부하 | 동작 | 근거 |
|---|---|---|
| **저이벤트율** | 스냅샷 없음. readout 시점 타임스탬프 | arbiter의 timestamp error가 이미 프레임보다 훨씬 작다. 홀드하면 오히려 나빠진다 |
| **고이벤트율** | 대기 집합을 스냅샷하고 그 순간을 전체 타임스탬프로 사용, arbiter로 배출 | readout latency가 타임스탬프를 오염시키는 구간이며, 스냅샷이 그 의존성을 제거한다 |

**부하 검출**: **활성 행 수** popcount. 64×64 배열에서 4096비트가 아니라 **64비트**이고, row 라인은 어차피 존재한다. 행/열 readout의 혼잡은 정확히 "여러 행이 경합하는 것"이다.

**디지털 범위 (중요)**: Gen3의 global hold는 픽셀 내부(in-pixel event memory)에 있으며 이는 아날로그 영역이다. **본 제안은 그것을 요구하지 않는다.** 스냅샷 레지스터는 **배열 경계의 평범한 디지털 레지스터**이며 픽셀은 전혀 바뀌지 않는다.

> **명시하는 한계**: in-pixel memory가 없으므로 픽셀은 readout 시점에 해제된다. 즉 **타임스탬프 이득만 얻고 dead time 이득은 얻지 못한다.** 손실 거동은 row/column 베이스라인과 동일하게 유지된다.

**설계 요구사항 — 정착 게이트**: 요청 집합이 `px_req ↔ held`로 **한꺼번에** 바뀌면 두 arbiter tree가 전체 재정착하며 grant가 글리치한다. 이때 출력단을 `T_SETTLE` 동안 동결해야 한다. 이는 모델링 편의가 아니라 **대량 요청 변경 시 arbiter의 정착 시간이 필요하다는 실제 설계 제약**이다.

### 5.3 제안 구조의 실측 결과

동일 자극·동일 측정 코드에서 스냅샷 기능만 켜고 끈 비교(64 픽셀, iid Poisson).

| offered [Meps] | σ_ts 베이스 → **제안** | worst 베이스 → **제안** | hold 비율 |
|---|---|---|---|
| ≤300 | 변화 없음 | 변화 없음 | 0~1.5 % |
| 400 | 3.25 → **2.54** | 38.7 → **38.6** | 11.7 % |
| 500 | 6.82 → **4.66** | 65.8 → **60.6** | 47.6 % |
| 700 | 25.96 → **10.98** | 178.2 → **100.9** | 96.5 % |
| 1000 | 61.85 → **17.59** | 403.2 → **144.1** | 98.3 % |

**포화에서 timestamp error 3.5배, worst-case readout latency 2.8배 개선.**

**저이벤트율에서는 베이스라인과 동일**하다 — hold 비율이 0이므로 스냅샷이 걸리지 않는다. 적응 동작이 의도대로 작동한다.

#### 대가

| 항목 | 베이스라인 | 제안 | 차이 |
|---|---|---|---|
| 용량 (포화 throughput) | 538.4 Meps | 519.1 Meps | **−3.6 %** |
| 손실률 @1000 Meps | 45.82 % | 47.76 % | **+1.94 %p** |
| readout latency 평균 @1000 | 55.3 ns | 58.9 ns | +6.6 % |

대가의 출처는 §5.2의 **정착 대기**다. 스냅샷을 걸고 푸는 매 전환마다 출력단을 정지시켜야 하므로 그만큼 처리율이 줄어든다. 전환이 잦은 중간 부하(500~600 Meps)에서 손실 증가가 가장 크다.

> **읽는 법**: readout latency 평균은 오히려 나빠졌고 timestamp error는 3.5배 좋아졌다. 이것이 제안의 본질이다 — **이벤트가 나가는 시각을 앞당긴 것이 아니라, 이벤트에 붙는 시각이 나가는 순서에 의존하지 않게 만든 것**이다.

#### 자극 공간 구조에 따른 검증

동일 비교를 네 가지 자극에서 반복했다(4픽셀 클러스터, 총 이벤트율 고정).

**포화(1000 Meps)**

| 자극 | throughput 베이스→제안 | **σ_ts 베이스→제안** | worst 베이스→제안 |
|---|---|---|---|
| iid Poisson | 538.4 → 519.1 | 61.85 → **17.59** | 403.2 → 144.1 |
| 가로 엣지 | 538.2 → 519.1 | 55.59 → **18.34** | 350.6 → 167.4 |
| 세로 엣지 | 538.2 → 518.9 | 61.69 → **18.52** | 413.4 → 159.9 |
| 블록 | 538.3 → 519.0 | 58.09 → **18.44** | 354.0 → 171.1 |

**베이스라인의 σ_ts는 자극에 따라 55.6~61.8로 흩어지지만, 제안 구조는 17.6~18.5로 모인다.** 스냅샷이 걸리면 timestamp error가 트래픽의 공간 구조가 아니라 **스냅샷 드레인 시간에만** 의존하기 때문이다. 용량 대가도 전 자극에서 −3.6 %로 동일하다.

#### ★ 부하 검출기는 "부하"가 아니라 "공간 확산"에 반응한다

**1 Meps — 사실상 무부하 구간**

| 자극 | 스냅샷 비율 | σ_ts 베이스→제안 |
|---|---|---|
| iid Poisson | 0.0 % | 0.042 → 0.042 |
| 가로 엣지 | 0.0 % | 2.092 → 2.092 |
| **세로 엣지** | **0.2 %** | **2.092 → 0.292 (7.2배)** |
| 블록 | 0.0 % | 2.092 → 2.092 |

세로 클러스터의 4픽셀은 **서로 다른 4개 행**에 떨어지므로 활성 행 수가 즉시 임계값에 도달한다. 무부하인데도 스냅샷이 걸리고, 동시에 발생한 네 이벤트가 **같은 타임스탬프**를 받는다.

**이는 P1(동기 버스트 아티팩트)이 문제가 되는 바로 그 상황이다.** 활성 행 수라는 지표가 의도했던 것보다 정확한 것을 재고 있었다 — 혼잡이 아니라 **공간적으로 동시에 발생한 이벤트**를.

#### 검출기의 방향 비대칭 — 개선 여지

가로 엣지는 한 행에 몰리므로 활성 행 수가 1이며, 검출기가 잡지 못한다. 그래서 저부하 가로 클러스터에서는 개선이 없다.

이는 §4.3에서 확인한 압축의 방향 의존성과 **정확히 상보적**이다.

| | word-serial 압축 | 스냅샷 트리거 |
|---|---|---|
| 가로 엣지 | **1.64×** | 걸리지 않음 |
| 세로 엣지 | 1.02× | **즉시 걸림** |

→ **활성 행 수에 활성 열 수를 더하면 방향 중립이 된다.** 추가 비용은 `NCOL` 비트 population count 하나이며, 열 라인 역시 이미 존재한다. 실측에서 직접 도출된 개선안이다.

### 5.4 4구조 종합 비교

동일 조건: **64 소스 · 6-bit 주소 · 동일 출력단**. 차이는 오직 readout 구조.

| | 저부하 σ_ts | 포화 σ_ts | 포화 worst | 용량 [Meps] | arbiter 셀 | 준안정성 |
|---|---|---|---|---|---|---|
| flat micropipeline tree | **0.007 ns** | 40.1 | 232.5 | **539** | 63 | 있음 |
| row/column (전통) | 0.042 ns | 61.8 | 403.2 | 538 | 14 | 있음 |
| scan (Gen3) | 34.6 ns | 31.7 | **236.6** | 454 | **0** | **없음** |
| **제안 하이브리드** | 0.042 ns | **17.6** | **144.1** | 519 | 14 | 있음 |

**제안 구조가 양 구간 모두에서 최선이다.**

- **저이벤트율**: arbiter 계열의 즉응성을 그대로 유지(0.042 ns). scan 대비 **820배**.
- **포화**: σ_ts 17.6 ns 로 scan(31.7)보다 **1.8배**, row/column(61.8)보다 **3.5배** 우수. worst-case도 144 ns 로 네 구조 중 최소.
- 스냅샷 주기가 **고정 프레임이 아니라 드레인 시간에 적응**하기 때문이다.
- 대가는 용량 −3.6 %(538 → 519 Meps)이며, 그래도 scan(454)보다 14 % 높다.

### 5.5 사양 확정과 그 근거

| 항목 | 결정 | 근거 |
|---|---|---|
| 동기화 방식 | 4-phase bundled-data + semi-decoupled micropipeline | 표준셀 합성 가능성이 대회 제약(Cadence)과 직결. structural 경로 실동작 확인 |
| 파이프라인 소자 | 표준 edge-triggered FF | rising edge 캡처만 필요하므로 transparent latch 불필요 |
| 중재 셀 | cross-coupled NAND mutex + **명시적 회전 우선순위** | 무상태·starvation 불가. 공정성을 아날로그 물성에 의존시키지 않기 위해 회전 추가 |
| 타임스탬프 위치 | readout 시점 (부하 시 스냅샷 시점) | in-pixel은 픽셀 면적 급증. front-end 잡음이 이미 수백 µs |
| 이벤트 포맷 | 베이스라인 32-bit AER + 그룹 포맷 | 압축 이득이 장면 방향에 의존함을 실측 반영 |
| **배열 크기 N** | **64×64 = 4096** | 3인 팀 layout 가능 규모, log₂N=12로 depth 효과가 드러남 |
| **tile 수 M** | **기준안 M=4**, 비교축 {1,2,4,8,16} | §5.6 |

### 5.6 tile 수 M의 선정 — worst-case가 지배한다

**실측 스케일링 법칙 3건** (NCH 8 → 128, 16배 범위):

| # | 법칙 | 내용 |
|---|---|---|
| ① | **Δ는 depth와 무관** | 배열 16배 성장에 용량 변동 0.67% (537.8 → 541.3 Meps). 파이프라인이므로 처리율은 출력 사이클이 결정 |
| ② | **τ₀는 depth에 선형** | `τ₀ = 0.520 ns × depth`, 절편 0 |
| ③ | **버스트 latency 닫힌 형태** | `L(ch) = τ₀ + bitrev(ch) × Δ` |

일반적으로 tile 분할의 이득은 `τ₀ ∝ log₂(N/M)`으로 설명되지만, **실측상 그 항은 작다**(단당 0.52 ns). 지배적인 것은 **버스트 worst-case가 tile 크기에 선형**이라는 사실이다.

`N = 64×64`, 전체 픽셀 **10% 동시 이벤트**(= 410 event) 기준:

| M | 깊이 | τ₀ | tile당 이벤트 | **버스트 worst** | 총 throughput |
|---|---|---|---|---|---|
| 1 | 12 | 6.24 ns | 410 | **767 ns** | 539 Meps |
| **4** | 10 | 5.20 ns | ~102 | **195 ns** | 2,156 Meps |
| 16 | 8 | 4.16 ns | ~26 | **52 ns** | 8,624 Meps |

**M을 늘리면 worst-case는 M에 반비례하고 throughput은 M배가 된다. τ₀ 이득은 부수적이다.** 대가는 출력 채널 M개다.

**→ M은 τ₀가 아니라 worst-case 목표로 정한다.** 비교 기준: 상용 비동기 센서는 10% 동시 이벤트에서 worst-case 약 1 ms이며, 본 설계는 같은 조건에서 sub-µs를 목표로 삼을 수 있다.

## 6. 설계 및 검증

### 6.1 목적

1차 주제는 "설계 방향 제시"이지만, **제시하는 방향이 실제로 성립하는지를 스스로 검증하지 않으면 근거가 없다.** 따라서 4개 구조를 모두 RTL로 구현하고 동일 조건에서 측정했다.

### 6.2 구현 목록

| 파일 | 역할 |
|---|---|
| `mutex.v` | 2-input 상호배제 소자 (arbiter cell) |
| `c_element.v` | Muller C-element |
| `delay_chain.v` | bundled-data matched delay |
| `aer_node.v` | 2-input arbitered encoder node (semi-decoupled 이중 C-element) |
| `aer_tree.v` | 임의 깊이 바이너리 트리 인코더 (재귀 인스턴스화) |
| `arb_tree.v` | level-mode arbiter tree, one-hot grant (전통 AER 방식) |
| `aer_rowcol.v` | row/column readout — 베이스라인 B1/B2 |
| `aer_scan.v` | 동기 scan readout — 베이스라인 B3 |
| `aer_hybrid.v` | **제안 구조** — 부하 연동 스냅샷 타임스탬핑 |

### 6.3 검증 방법 — 6단계 테스트벤치

| PHASE | 내용 | 판정 |
|---|---|---|
| 0 IDLE | 자극 없이 500 ns 대기 | 자발 동작이 있으면 자유발진 |
| 1 DIRECTED | 채널을 하나씩 순차 발화 | 주소 인코딩 정확성 |
| 2 BURST | 전 채널 동시 발화 | grant 교대 경합, silent loss 검출 |
| 3 POISSON | 단일 부하 통계 | 보존 검사, 지표 산출 |
| 4 SWEEP | 1 → 1000 Meps 로그 스윕 | 용량 곡선, timestamp error |
| 5 FAIRNESS | 동기 버스트 200회 반복 | 서비스 순위 편향 (P1) |

**자극 모델**은 문헌과 동일하게 맞췄다 — Poisson 도착 + **per-source one-slot gating**(픽셀이 pending 요청을 1개만 보유하며, 초과분은 중앙 큐가 아니라 소스에서 손실). 추가로 **공간 클러스터링 자극**(가로/세로/블록)을 구현해 iid Poisson의 한계를 보완했다.

### 6.4 계측 설계 — 무엇을 재는지 명확히 한다

| 지표 | 정의 |
|---|---|
| throughput | 완료 이벤트 / 경과시간 [MEvent/s] |
| readout latency | 발생 → 출력 [ns], mean·min·**worst** |
| **timestamp error** | 타임스탬프 시각 − 발생 시각. arbiter에서는 readout latency와 동일하지만 scan/제안 구조에서는 다르다 |
| σ_between / σ_within | 타임스탬프 오차의 일원배치 분산분석 |
| loss | 소스 측 one-slot gating 손실률 [%] |
| 보존 검사 | 노드별 래치/전달 수, in-flight ≤ 노드 수 |
| 서비스 rank | 동기 버스트에서의 배출 순위 (P1 지표) |
| k (버스트 길이) | 행 grant당 이벤트 수 → word-serial 비트/이벤트 |

**worst-case를 명시 측정한다.** 기존 문헌 대부분이 소수 픽셀만 자극한 평균을 보고하여 worst-case 성능을 반영하지 못한다는 방법론적 비판이 있으며, 이를 반영했다.

### 6.5 결과의 신뢰성 — 자기일관성 및 문헌 정합

측정이 옳다는 것을 독립적으로 확인했다.

| 검증 | 이론 | 실측 |
|---|---|---|
| 손실률 = 1 − 용량/offered (내부 손실 0일 때) | 46.22% | 45.60% |
| scan σ_ts = T_frame/√12 | 34.35 ns | **34.6** |
| scan ts_mean = T_frame/2 | 59.5 ns | **58.4** |
| scan worst = 2·T_frame | 238 ns | **236.6** |
| scan loss = 1−(1−e^−ρ)/ρ, ρ=0.186 | 8.6% | **8.479** |
| **Boahen 2000: σ/mean ≈ 0.93 (95% 부하)** | 0.93 | **1.01 ~ 1.12** |

**마지막 항목**: Boahen이 2000년에 보고한 "latency ≈ temporal dispersion"을 본 설계의 row/column 구조(= 그가 분석한 바로 그 구조)에서 재현했다. 지수분포 큐의 서명이며, 측정이 문헌과 정합함을 보이는 독립 검증이다.

### 6.6 검증 범위와 한계 — 정직하게 명시

| 항목 | 상태 |
|---|---|
| 기능 검증 (behavioral) | ✅ 완료 |
| 기능 검증 (structural, 합성 대상 경로) | ✅ 완료 — 용량이 behavioral과 0.01% 일치 |
| 타이밍 클로저 (STA) | ❌ **미완** — Cadence 환경 미확보 |
| 면적 (µm²) / 전력 (fJ/event) | ❌ **미완** — PDK 필요. 게이트 등가(GE) 상대 비교까지만 가능 |
| 제안 구조 배출 정합성 | ✅ 완료 — 래치·acknowledge·배출 3자 계수 전 구간 일치 |

**시뮬레이션 지연값은 가공값이다.** 절대 성능을 실리콘과 직접 비교하지 않으며, 의미 있는 것은 **구조 간 상대 비교**와 **곡선의 형태**다.

### 6.7 검증 중 발견하여 수정한 설계 결함

기능 검증 과정에서 시뮬레이션으로만 드러나는 결함 세 건을 찾아 수정했다. 세 건 모두 **소규모·저부하 시험으로는 통과하는** 종류였다. 상세는 별도 문서 참조.

| 결함 | 드러나는 조건 | 수정 |
|---|---|---|
| **입력 인에이블에 `~r_ack` 누락** | acknowledge 왕복이 가장 긴 노드에서만 | 출력 채널이 완전히 idle일 때만 새 이벤트 admit |
| **arbiter가 동시 도착을 해소 못 함** | 두 요청이 정확히 같은 시각일 때만 (§P9) | 소자 mismatch 모델링. 표준셀 한계의 직접 증거 |
| **재구성 시점 판정 오류** | 스냅샷 진입/이탈 전환에서만 | 아래 |

#### `cin == 0`은 "유휴"를 뜻하지 않는다

제안 구조에서 배출된 주소 중 약 0.02 %가 어떤 픽셀도 acknowledge하지 않은 채 나갔다. 래치·acknowledge·배출을 각각 세어 원인을 좁혔다.

C-element는 **입력에서 래치하고 유지**한다. `granted`와 입력 인에이블이 아무리 짧게라도 겹치면 내부 상태가 서고, 출력은 한 전파지연 뒤에 **반드시** 어서트된다. 그 지연 동안 출력을 샘플링하면 "유휴"로 보이지만 트랜잭션은 이미 확정되어 있다. 그 창에서 arbiter 입력 집합을 바꾸면 **확정된 트랜잭션 밑에서 grant가 빠져나가** 선택된 픽셀 없이 주소가 래치된다.

관측이 이를 확정했다 — 결함 발생 시점의 상태가 **전부 동일**했다(정착 게이트 어서트 중, 스냅샷 직후, 행 grant 0).

**수정**: ① 정착 게이트를 먼저 내려 새 트랜잭션을 차단 → ② C-element 전파지연만큼 대기하여 이미 확정된 트랜잭션을 해소 → ③ 출력단이 완전히 정지할 때까지 대기 → ④ 그제서야 입력 집합 변경.

> **일반화**: 비동기 회로에서 중재 입력 집합을 재구성하려면 출력단이 실제로 정지해야 하며, **"정지"의 판정에 제어 자신의 전파지연을 포함해야 한다.** 이는 경계 스냅샷 방식이 지불하는 숨은 비용이다 — 픽셀 내부에 메모리를 두면 요청 하강이 픽셀을 거치면서 이 창이 자연히 닫힌다.

## 7. 2차 주제와의 연계

Digital 2차 주제(n×m 시각신경 → N×M world memory 매핑)를 고려하면, 1차에서 **회전 기반 pixel→world 좌표 리매핑이 쉬운 주소 표현**을 채택하는 것이 유리하다.

본 제안의 주소 구조는 `{row_addr, col_addr}`로 행·열이 분리되어 있어, 회전각에 따른 좌표 변환에서 두 축을 독립적으로 다룰 수 있다. 또한 스냅샷 단위로 이벤트가 묶이므로, **한 스냅샷의 이벤트 집합에 동일한 좌표 변환을 일괄 적용**할 수 있어 프레임 단위 리매핑과 자연스럽게 맞물린다.

## 8. 요약

**분석**: AER의 "통신 방식"은 데이터 포맷이 아니라 readout 메커니즘이며, 설계 목표는 타임스탬프 단위가 아니라 **readout worst-case latency**다.

**문제점**: 10개 항목을 도출하고, 그중 P1(unfair arbitration), P4(timestamp error), P6(확장성), P9(metastability)를 **자체 회로에서 정량 측정**했다. 특히 아티팩트의 정체가 **주소 공간의 결정론적 비트역순 패턴**임을 닫힌 형태로 규명했다.

**개선방법**: 아티팩트 저감에 **직교하는 세 레버**(tile 분할 / 중재 공정화 / 타임스탬프 분리)가 존재함을 실측으로 보이고, 각각의 효과와 대가를 정량화했다.

**설계 방향**: 비동기 arbiter와 동기 scan은 **이벤트율에 따라 교차**하며, 교차점을 자체 회로에서 실측했다(550 / 780 Meps). 이를 근거로 **부하 연동 스냅샷 타임스탬핑 + row/column 버스트 arbiter readout**을 제안하고, **양 구간 모두에서 기존 3구조보다 우수함**을 확인했다 — 포화에서 timestamp error **3.5배**·worst-case **2.8배** 개선, 대가는 용량 **−3.6 %**.
